# Docs Tutor

**루미버스용 · 비공식 (Unofficial, for Lumiverse)**

설치된 서버의 공식 가이드에서 초보자용 문서를 골라 월드북(World Book)을 만들고, 선택한 캐릭터에 연결하는 Spindle 확장입니다. 문서는 **영어 원문**으로 보존하고, 캐릭터에는 **한국어 설명 + 한국어(English) 용어 병기**를 지시합니다. 확장 자체는 번역이나 모델 생성을 호출하지 않습니다.

Lumiverse 공식 확장이 아니며 해당 팀이 제작하거나 승인·보증·지원하지 않습니다.

## 대응 버전

| 항목 | 내용 |
|---|---|
| 이 확장 | v0.1.1 |
| 검증한 호스트 | **Lumiverse 1.2.5** (`staging` 브랜치 `cec7676c`) |
| 검증한 문서 | 같은 서버(Lumiverse 1.2.5)에 들어 있는 공식 가이드 (`/api/v1/docs/catalog`, `/api/v1/docs/file/:encoded`) |
| 설치 가능 범위 | `spindle.json`에 최소 호스트 버전 필드가 없어, 호스트가 버전으로 설치를 막지 않습니다 |
| 검증 날짜 | 2026-10-17 (v0.1.0 설치·실행) · 2026-10-22 (v0.1.1 http 접속 fixture) |

- **Lumiverse 1.2.5에서만 설치·실행을 검증했습니다.** 다른 버전에서도 설치는 될 수 있지만 동작은 보증하지 않습니다. 캐릭터·월드북 SDK나 공식 가이드 엔드포인트가 바뀌면 동작하지 않을 수 있으니, 문제가 생기면 사용 중인 Lumiverse 버전을 함께 알려 주세요.
- v0.1.1은 휴대폰에서 Tailscale 주소처럼 localhost가 아닌 `http://` 주소로 열 때 캐릭터 목록·생성 요청이 "crypto.randomUUID is not a function"으로 실패하던 문제만 고쳤습니다(요청 ID 생성 방식 변경). 이 변경은 단위 테스트와 http fixture(Chromium·Firefox)로 확인했고, Lumiverse 1.2.5 설치·실행 검증은 v0.1.0 때 한 것입니다.
- 가이드는 설치된 서버에서 읽기 때문에 Lumiverse를 업데이트하면 결과도 달라질 수 있습니다. 화이트리스트 문서가 없어지면 쓰기 전에 멈춥니다.

## 사용법

1. Spindle 확장 설치 화면에 이 저장소의 GitHub 주소를 입력합니다.
2. 요청한 캐릭터·월드북 권한을 확인하고 활성화합니다.
3. **📚 버튼 → 캐릭터 선택 → 로어북 생성 + 장착** 순서로 실행합니다.
4. 선택한 캐릭터와 대화하며 “월드북이 뭐야?”처럼 질문합니다.

원작의 버튼·체크박스·로그·드래그 흐름과 **로어북 생성 + 장착** 문구를 유지합니다. 실제 저장 대상은 호스트의 월드북입니다. 화면 색·입력·테두리는 호스트 테마 변수를 따릅니다. 설명의 서버명과 오류 안내만 호스트에 맞췄고, 키보드 열기·Escape 닫기·탭 순환을 보강했습니다.

설치·실행에는 캐릭터/월드북 SDK, 프론트엔드 메시징, 공식 가이드 catalog/file 엔드포인트를 제공하는 호스트가 필요합니다. 설치 권한이 없는 계정에서는 관리자에게 설치를 요청하세요.

## 문서와 단어집

- 문서는 현재 사용 중인 **같은 서버**의 `/api/v1/docs/catalog`와 `/api/v1/docs/file/:encoded`에서 읽습니다. 문서 원본을 변경하거나 이 저장소에 재배포하지 않습니다.
- 전체 문서 대신 `src/core.js`의 명시적 화이트리스트만 사용합니다. 파일이 누락되면 쓰기를 시작하지 않고 오류로 멈춥니다.
- 문서 본문은 키워드 엔트리로 나누며, 영어·한국어 트리거와 출처를 붙입니다. 재귀 활성화는 사용하지 않습니다.
- 공개된 기본 [한↔영 단어집](./glossary.json)을 포함합니다. 상시 엔트리는 **한국어 답변 지시 + 단어집 1개**입니다.
- 설치된 호스트의 Vite 한국어 로케일 청크가 있으면 **en↔ko 동일 키의 짧은 UI 라벨**을 우선합니다. 한국어 청크가 없거나 구조가 바뀌면 내장 단어집으로 돌아갑니다. 사용자 작성 이름·내용은 번역하지 않습니다.
- 호스트가 공식 로케일 자료 API를 제공하지 않아 로케일 발견은 빌드 구조에 의존합니다. 알려진 `assets/i18n/en-*`, `ko-*` 청크만 읽으며, 소스 문자열을 `eval`하지 않습니다.
- 설정 기준 문서(Bible), 로어북(Lorebook), 월드북(World Book), 대리 작성(Impersonate), 모의 실행(Dry Run), 유도 생성(Guided Generation), 초상화(Portrait)를 구분합니다.

## 데이터·권한·갱신

- `characters`: 캐릭터 목록 읽기, 선택한 캐릭터의 월드북 연결만 갱신합니다. 기존 연결을 보존합니다.
- `world_books`: 확장이 소유권 메타데이터를 붙여 만든 월드북·엔트리만 갱신합니다. 같은 이름의 사용자 월드북은 건드리지 않습니다. 확장 월드북 안에 사용자가 추가한 미관리 엔트리도 보존합니다.
- 확장 전용 사용자 저장소에는 만든 월드북 ID만 저장합니다. 브라우저에는 📚 버튼 위치만 저장합니다.
- 서버 원문과 UI 로케일 외의 외부 서비스로 요청을 보내지 않습니다. API 키·사용자 대화·연결 설정은 읽지 않습니다.
- 항목 갱신 후에 오래된 관리 엔트리를 제거합니다. 중간 실패 시 부분 갱신이 남을 수 있으므로 로그를 확인하고 재실행하세요. 같은 확장 런타임의 동시 작업은 거부합니다.
- 비활성화 시 버튼·팝업·리스너·진행 중 문서 요청이 정리됩니다. 이미 저장한 월드북과 캐릭터 연결은 삭제하지 않습니다. 제거하려면 앱에서 해당 연결과 월드북을 직접 관리하세요.

답변 지시가 주입되어도 실제 모델이 용어·언어를 반드시 지킨다는 보장은 없습니다. 키워드 결과는 호스트의 월드북 토큰 예산·항목 수·대화 설정에 영향을 받습니다. 문서의 매크로 예시는 호스트 프롬프트 조립 단계에서 해석될 수 있습니다.

## 개발·검증

Node.js와 Bun이 필요하며 별도 npm 의존성은 없습니다.

- `npm test`: 변환·소유권·실패 복구·문서/로케일 어댑터 테스트
- `bun run build.mjs`: 백엔드·프론트엔드 ESM 빌드
- `npm run qa:insecure`: localhost가 아닌 http 주소(보안 컨텍스트 아님)에서 Chromium·Firefox로 fixture를 열어 캐릭터 목록 요청이 되는지 확인합니다(`PLAYWRIGHT_MODULE`, 선택: `FIREFOX_BIN`·`CHROMIUM_BIN`). 설치 검증이 아닙니다.
- `tests/browser.py`: Playwright + Chromium headless fixture. `--docs`로 제공한 문서는 로컬 테스트에만 사용하며 저장소에 넣지 마세요.

`dist/backend.js`, `dist/frontend.js`는 Git 추적 대상입니다. 소스 변경 시 같이 재빌드해야 합니다. fixture 검증은 실제 Spindle 설치·권한 승인·프롬프트 미리보기 검증을 대체하지 않습니다.
